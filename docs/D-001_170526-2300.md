## CONTEXT 📝

Jotting down my ideas for the project and issues I noticed within the logic of the game.

### CONFLICT 01 ⚠️

Right now the program gives a straight forward advice when user makes a guess, it's either too high or too low... What qualifies as "too" much of a something? What if the number is the one that follows? It doesn't sound correct to say that is too low and you should try higher.

#### IDEA 💡

What about using a suggestion that fits better to the guess? Like the child's game where you had to look for an object and cold = bad = far and hot = good = closer? This definetely would add more information and help the user...

But having both means it will be too easy.

#### ALTERNATIVES / OPTIONS ↔️

##### Replacing the distance with the temperature feedback 🎯

Keeping the contextual recommendations based on context and history of user's input but changing the binary response to a proximity-based feedback that works in a hot/cold mechanic. Instead of telling the player the direction we talk to the user in terms of distance. Even adding different comments randomly selected depending on the tier.

*PROS* : More fun, arcade feel, encourages "hunting"

*CONS* : Requires tuning ranges

#####  Keep both but unlock temperature when too many attempts 🎯

Keeping the binary feedback at the start of the game but after 5 failures adding the temperature feedback

*PROS* : Keeps the early game challenging, rewards persistence

*CONS* : Complex logic

## DECISION ✅

I will replace binary feedback with a 7-tier temperature mechanic based on absolute distance from target.

## CONSEQUENCES 🚨

- *POSITIVE*
    - More engaging
    - Arcade feel
- *NEGATIVE*
    - Possibility of solving too fast if ranges not set accordingly. Requires careful tuning of thresholds.
- *RISKS* 
    - Haven't percieved any at the current moment.
