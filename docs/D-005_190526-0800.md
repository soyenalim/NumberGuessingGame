# DOC 005 | Player Persistence & Profiles

## CONTEXT 📝

Arcade games need memory. Players want to see improvement over time.
Issue #2 requires saving player profiles between sessions.

## ISSUE #2 

### PLAYER FLOW
1. Show existing players + "New Player" option
2. If existing: load profile, welcome back
3. If new: validate name, create empty profile, start game
4. After win: update stats if better, save to JSON

### 3 LEADERBOARDS

| Leaderboard        | Stat           | Sort                         | Champion       |
|--------------------|----------------|------------------------------|----------------|
| **SPEED DEMONS**   | best\_time     | Ascending (lower = better)   | Fastest solve  |
| **LOGIC MASTERS**  | best\_attempts | Ascending (lower = better)   | Fewest guesses |
| **NUMBER JUNKIES** | games\_played  | Descending (higher = better) | Most dedicated |

### VALIDATION RULES
- Empty? → ValueError: Name cannot be empty
- 4 chars? → ValueError: Max 4 characters
- Not alphanumeric? → ValueError: Letters and numbers only

### BUGS FOUND & FIXED 🐛

#### Bug 1: get_player() returned method object

Symptom: get_player("dev0") showed <built-in method copy...>
Cause: .copy without parentheses (returned the method, not a copy)
Fix: Changed to .copy()
File: src/persistence.py, line 73

#### Bug 2: update_stats() case-sensitive lookup

Symptom: update_stats("dev0", ...) raised KeyError: 'dev0'
Cause: Direct dict lookup with lowercase name, but JSON stores uppercase keys
Fix: Added case-insensitive search loop to find actual key, then used found_name for dict access
File: src/persistence.py, lines 83-94

## DECISIONS ✅

- JSON file: `data/players.json`
- NOT gitignored — portfolio shows real data, test players marked via `is_test` flag
- Max 4 chars, uppercase display, case-insensitive matching
- Allowed characters: letters + numbers (`isalnum()`)
- Stats: best_attempts, best_time, games_played, total_guesses, is_test

## DATA STRUCTURE

```json
{
  "players": {
    "NAME": {
      "best_attempts": int,
      "best_time": float,
      "games_played": int,
      "total_guesses": int,
      "is_test": bool
    }
  }
}

## CONSEQUENCES 🚨
- **POSITIVE:** 
    - Personalization increases replay value; three leaderboards create multiple "win" conditions

- **NEGATIVE:** 
    - File I/O adds failure modes (corrupted JSON, missing file, concurrent access)

- **RISKS:** 
    - data/players.json committed to Git means personal scores are public; acceptable for portfolio but not for real app
